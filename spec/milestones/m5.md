### 2. Codegen decisions

1. **`[setup.backends]` is keyed by backend name**, not origin alias — the
   resolver looks backends up via `Backend::from_name(origin.backend)`
   (`edge-fastly/src/resolve.rs`). Caught by a unit test, not the spec.
2. **`[local_server]` is preserved verbatim** when the target file already has
   one: it is Viceroy testing config, not derivable from `edge.toml` (D15).
   Regeneration is a fixed point — verified by diffing consecutive runs.
3. **KV namespaces omit `id`** in `wrangler.toml`: wrangler auto-provisions
   the namespace and writes the id back on first deploy (verified against
   the wrangler 4.125.0 config schema).
4. **Determinism**: origins sorted by alias; no map-iteration order leaks.

### 3. §14 open question 1 — resolved

"CF fetch permission syntax": verified 2026-08-24 against wrangler 4.125.0's
`config-schema.json` — **no `permissions`/fetch-allowlist key exists** (only
generic `unsafe.bindings`, which is not a fetch allowlist). Outbound `fetch`
is allow-by-default on Workers, so `edge-cli` emits no permission config and
the §7.5 fail-open-on-CF asymmetry remains documented, not configurable.
SPEC.md §7.2/§14 updated accordingly.
